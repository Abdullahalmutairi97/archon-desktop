# P5 — Native runtime parity and resource management

**Status:** in progress. Prime, Pi and Hermes are installed on the target workstation with pinned identities, headless start and native account material, and each completed a bounded provider turn (Prime and Pi on DeepSeek Flash, Hermes on its own provider) — see [installed runtime availability](releases/p5-runtime-availability.md). The registry publishes an adapter manifest per runtime. Codex is intentionally unused for this workstream. Conformance fixtures, native resource accounting and enforced isolation remain open. **Dependencies:** P3; P4 for integrated UX. Individual adapter work can proceed independently once the contracts are stable. **Outcome:** Hermes, Pi, Prime and Codex are selectable with truthful capabilities, scoped native authentication and managed MCP/skills.

## Scope

Keep provider/model, runtime, harness and execution environment distinct. Use native bindings behind a versioned Archon adapter/event contract. Unknown capabilities fail closed. Preserve existing Prime/Pi print paths until richer RPC paths have parity; preserve native histories and original runtime/cwd ownership.

## Checklist

- [ ] Publish adapter manifests with runtime version/executable digest, modalities, resume/fork/steer, approval/read-only/chat-only support, reconnect semantics and resource formats/transports. The registry now publishes a read-only executable digest and honest capability flags per runtime (never executing the runtime to probe a version); declared versions and the target-host identities are recorded in releases/p5-runtime-availability.md.
- [ ] Add conformance fixtures for prompt/stream/cancel/auth/approval/unsupported/resume/error behavior; validate before admission and again when binary/config identity changes.
- [ ] Pin and qualify Prime/Pi RPC, separate Hermes ACP registration and runner-owned Codex app-server stdio. Prime, Pi and Hermes each completed a bounded headless provider turn (Prime/Pi on DeepSeek Flash, Hermes on its own provider); Codex is intentionally unused for this workstream. RPC/ACP parity and conformance fixtures remain open. Do not silently fall back across runtimes or assume untested remote transports.
- [ ] Preserve imported native history restrictions until exact native resume mappings are validated. Reject cross-runtime or wrong-cwd resume.
- [x] Normalize allowlisted events with attempt/runner/generation identity. Malformed/unknown native events become diagnostics, not false completion. The engine stamps every runner event with the task id and attempt id (`tasks.py`), the runners report unparsable records and unhandled types as bounded `diagnostic` events with running counts (`native_diagnostics.py`, at most four per run), a turn that exits successfully with unreadable output and no answer fails closed instead of completing empty, and the desktop task panel renders the diagnostic without treating it as assistant output.
- [ ] Bound, redact, encrypt, restrict and expire optional diagnostic capture; disable raw capture when credentials cannot reliably be excluded. Diagnostic *records* are now captured with every bound the item asks for: capped entries and ledger, credential-shaped text redacted before the write, a private 0600 file, owner-only read and clear, and a TTL pruned on read and write. Raw stdout/stderr capture stays disabled by design and the endpoint says `rawCapture: false`, because a runtime's own text cannot be proven free of credentials; encryption at rest is not implemented (the file is private to the service account, which is the same boundary the item is about), so this box stays open on that point.
- [x] Bind approvals to action digest, attempt/native request, workspace generation and current policy. Deny stale/replayed/unauthorized/time-expired decisions; cancellation remains requested until termination is confirmed. The local Codex approval broker binds every prompt to the protocol request id plus the app-server process generation, and an answer is accepted only when the session, thread, task, kind, command or canonical changed paths, cwd, reason and file diffs all match exactly: a stale generation, an inactive task, an unknown or already-answered request, a path that became a symlink while the dialog was open, a disconnect and the timeout all resolve to deny (`desktop/src/main/adapters/codex/approvalBroker.ts` with `approvalBroker.test.ts`). File paths are canonicalised and protected-path checked before a prompt is shown. Cancellation intent survives teardown failure and blocks late output (`backend/tests/test_task_attempts.py`). Prime, Pi and Hermes run non-interactively with a mode validated before admission, so they have no approval prompt to bind; the secret broker binds its grants to the principal, tool, argument digest, attempt, workspace generation and ledger epoch.
- [ ] Add scoped provider/native authentication states and secret references without copying personal auth files between users. Owner-registered secret references and a scoped per-provider authentication state (`unavailable` / `unverified` / `verified`) are reported by `/api/local/secrets/references` and `/api/local/secrets/auth-states`; a state is derived from a resolvable reference plus a completed brokered call, i.e. it never claims provider capability or quota. Native auth-file hand-off between users remains open.
- [ ] Create resource definitions, assignments, install requests, immutable per-attempt snapshots, update/rollback pins and effective configuration provenance. Immutable per-attempt snapshots and effective configuration provenance are in place: the engine records each attempt's runtime identity, executable digest, manifest revision, capabilities, workspace generation, approval mode and pin state before the runner starts, in a private append-only store that refuses to overwrite a snapshot, with owner-only read and clear endpoints. Runtime pins record the accepted identity, keep previous digests for rollback, and report drift; the ledger never installs a binary. Still open: resource definitions/assignments, managed install requests and the update pipeline that would consume a rollback pin. Declarative definitions and their scope assignments now exist with a fixed precedence (`agent` > `workspace` > `project`) and an effective-configuration view that reports each declared digest against what this host measured (`current`, `drifted`, `unobserved`, `configuration-only`); the effective list is recorded in every attempt snapshot. Still open here: install requests and the managed installation/update pipeline (nothing in the definition ledger installs anything).
- [ ] Enforce hard policy before project/user/workspace/agent overrides; narrower scopes cannot widen denied permissions or secrets. A policy ledger now enforces a deny floor over the fixed chain `global` > `project` > `workspace` > `agent`: any matching deny decides, a narrower scope cannot widen it, and no entry is `unset` rather than allowed. `GET /api/local/policy/effective` explains the decision. It is enforced today on the brokered secret path (denied reference or tool refused at grant minting and again at invocation); other gates can adopt the same helper.
- [ ] Implement runtime-specific MCP transport/auth translators and versioned skill materialization. Inventory/configuration is not proof of connection; unsupported transports/formats are rejected.
- [ ] Approve managed executable installation/provisioning. Treat skill scripts as executable code and Markdown instructions as untrusted guidance rather than permission enforcement. Install requests are recorded with an explicit owner decision (approve or reject, once) on a recorded definition, and every row states that this server performed no installation. Still open: an actual provisioning pipeline that consumes an approval. An approved request can then be verified against the host (`POST /api/local/resources/install-requests/{id}/verify`), which records `provisioned`/`drifted`/`missing`/`unverifiable` from a real measurement and still performs no installation.
- [ ] For secret-backed restricted actions, use an isolated credential-holding broker that checks principal/tool/arguments/epoch, or equivalently enforced upstream credential scopes. Workspace code must not read broader credentials/process state or bypass the authorized channel with shell/direct HTTP. An isolated broker now holds this server's own environment-supplied credentials: an action needs a single-use grant bound to the principal, tool, exact-argument digest, attempt, workspace generation and ledger epoch, the broker performs the upstream HTTPS call itself and redacts the value from the bounded result, and the decision trail is owner-only. It is a capability boundary inside the server process, not an OS sandbox: no tool/MCP adapter consumes it yet, and bypass through a named tool versus shell/direct HTTP is not yet demonstrated.
- [ ] Stop/restart affected sessions when cached resources cannot be safely revoked. Never forward Archon credentials to MCP servers. Identity staleness is enforced: `GET /api/local/resources/sessions` reports the digest each conversation's newest attempt recorded against the digest installed now, and a resume is refused (409) when they differ or when a recorded identity cannot be matched at all; a conversation with no recorded identity is allowed and marked `unrecorded`. Stopping or restarting *running* work automatically is still not done: a live task is reported, never killed, by that check.
- [ ] Derive runtime/resource choices in the existing UI from capability/auth states and publish a tested compatibility table. The server view now derives its runtime choices from the manifest plus the provider authentication state, renders an unsupported capability as unsupported instead of hiding it, refuses to mark anything ready without a verified provider state, and publishes the matrix with its limits in `docs/releases/p5-runtime-compatibility.md`; a coverage test keeps the table aligned with the manifest.

## Validation and exit

- [ ] Each enabled pinned runtime completes a small file/test turn in its assigned workspace; auth/cancel/recovery/unsupported behaviors match the advertised matrix.
- [x] Malformed JSONL, subprocess loss, timeout/approval replay and indirect denied execution paths have regression coverage. Malformed/unknown native records: `backend/tests/test_native_diagnostics.py` (including a bounded flood and wrong-shaped fields) and the new capture tests in `backend/tests/test_diagnostic_capture.py`. Subprocess loss mid-turn: `test_tasks.py` never retries a disconnect with or without streamed output, `test_prime_runner.py` terminates the tree when event handling fails, `test_native_cancel_gate.py` reaps before releasing, and `test_task_recovery.py` covers restart recovery. Timeout and approval replay: `desktop/src/main/adapters/codex/approvalBroker.test.ts` denies after timeout, disconnect, a replaced process or an inactive task, `test_secret_broker.py` reports replay and denies expired/stale-epoch/stale-generation grants, and `test_resume_evidence.py` refuses replaying an attempt's own completion. Indirect denied execution: `test_child_env.py` strips ambient secrets per scope and `test_secret_broker.py` proves the environment channel never carries a broker source key, the named-tool path is bound to principal/tool/arguments and redacts reflected values. The shell/direct-HTTP half of that last path remains open in the following item, not here.
- [ ] A forbidden secret-backed operation fails through both the named tool and shell/direct HTTP; broker/process isolation or upstream scopes prevent the effect. The named-tool half is covered, and the environment channel is filtered. The shell/direct-HTTP half is **not** demonstrated and is now measured: the server clears its dumpable flag so `/proc/<server>/environ` is denied to other same-uid processes, but a same-uid process can still write the broker ledger and retarget where the credential is sent (reproduced: the broker sent it to an attacker-chosen origin), can reach the pairing socket, and can reach a provider origin directly. Closing it needs an enforced OS boundary around every workspace-capable process or real upstream scopes; the running instance on this host was remediated on 2026-09-28 with a `sitecustomize` hook in its unit (verified: `PermissionError` on `/proc/<pid>/environ`, health 200, rollback documented), while an unrelated auth service and the harness processes still expose their environments. See [same-uid exposure evidence](../releases/p5-same-uid-exposure-evidence.md).
- [ ] No cross-user auth or secret values appear in API/UI/logs. Resource scope precedence, incompatible transport, update rollback and active revocation pass.
- [ ] Compatibility records include binary/version/digest, date, fixture/native evidence and limits. Unavailable credentials mark that adapter unverified, never ready.

Known blockers: exact installed runtime versions, native API behavior/accounts, extension/MCP bridge compatibility, authenticated tool availability and demonstrable credential isolation. Current upstream documentation alone is not qualification of an installed executable. Jev/Laya are optional advisers and are not required for agent operation or permissions. The target workstation now has the full runtime roster installed (see releases/p5-runtime-availability.md); the remaining blockers are behavioral qualification and enforcement, not availability.
