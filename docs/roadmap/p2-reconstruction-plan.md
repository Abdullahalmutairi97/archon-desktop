# P2 bounded same-stack reconstruction plan

Astra plan/review, 26 September 2026. This is the bounded source-reconstruction route. P2A's synthetic build and pure models may run independently of C2/P1D, but the current scheduling priority is to finish remaining P1 implementation before opening P2 code work. P2B backend transport and credential integration remain gated on reviewed P1D interfaces and checks. The historical tree is not the official v0.3.0 source. No product implementation or native launch was performed for this plan.

## Evidence and starting decision

- Official frozen v0.3.0 parent ASAR remains unavailable; its SHA-256 stays `36d3ae03bd6b20c4e9ea5fc690461ef972b16eb0c9433bfb1305daeb068e549b`.
- Historical Electron/React tree: commit `69bcf1ecb25e4004c11576d3becdb3cb2d266767`, 102 recovered files verified against Git blob hashes and byte sizes. Its package label is 1.0.0 and README explicitly excludes v0.3.0 source provenance. The source inventory records the recovery evidence; the build must include provenance for every reused input.
- Twenty unique recursive trees across 24 main-history commits contain no separately tracked ASAR/source map. Both historical ZIPs are design prototypes/assets/support scripts; neither supplies Electron source or ASAR. Other unavailable refs/expired artifacts are not proven absent.
- Build a separate authored `desktop/` tree in the active repository. Keep `current/`, its baseline hashes and candidate builders/tests unchanged as the frozen recovery/comparison path. New normal source builds must not require a private ASAR or run bundle string replacement. Import useful behavior deliberately, with origin+transformation records per module.
- Use a distinct development app ID, executable/artifact name and isolated user-data namespace until release qualification. A development package version/build channel must explicitly say reconstruction (for example a prerelease tag selected consistently with docs/versions.md), and About/build metadata must include source commit plus `baselineParity: unverified`. Do not alter the official Desktop baseline or report legacy 1.0.0 as a newer release. Disable automatic update/install in this route until a separately reviewed update workflow exists.

The work is several review increments, not one source-copy patch. Pure-model extraction and an isolated shell are bounded; matching native browser/terminal/credentials and unknown v0.3 layout details are the larger uncertainty. Each increment can be built/tested independently and published without claiming full P2 completion.

## P2A — Authored source foundation and pure behavior (first executable increment)

Outcome: a fresh Git checkout can install pinned dependencies, typecheck/test and build an isolated development shell without private ASAR. Shell is clearly a reconstruction and uses synthetic state until trusted transport is integrated. Source build success is useful even while native/release parity remains unqualified.

Worker A — build/provenance: owns desktop/package.json/package-lock.json, Electron/Vite/TS/Vitest config, desktop/build assets selected for reuse, scripts/build-manifest and third-party license inventory, root build scripts/CI additions only by agreement with root. Import exact needed source/assets with origin hashes recorded. Do not run recovered capture/provision/verify scripts against the local machine; inspect/rewrite only isolated replacements. Resolve dependencies from the recovered lockfile, pin package.json to exact versions, pin Node version and CI image/digest, and verify versions/security constraints using primary package/Electron documentation before changing anything. No unreviewed blanket upgrades or unpinned CDN dependencies. `npm ci` must reproduce the lock, not rewrite it. Package-only allowlist excludes .env, local profiles, test histories, archives, manifests containing secrets, source-reference scripts and private screenshots.

Worker B — pure domain ports: owns desktop/src/shared/domain/{ide,queue,snapshot,identity}.ts and fixture parity tests. Preserve current helpers' edge cases; explicitly normalize backend roles/status/envelopes before artifact collection. No filesystem, process spawning or IPC from these modules.

Worker C — renderer shell/reference layout: owns desktop/src/renderer/{shell,appearance,...} plus synthetic fixture views and visual smoke definitions. Uses shared typed domain APIs, no main/preload changes. Preserve tokens/layout/shortcuts/preference values rather than creating a new design. Prioritize 1440x900 and min-size1040x680 historical dimensions plus narrow/RTL and maximum font scale. Mark screenshots as reconstruction/reference comparisons, not verified installed-v0.3 parity. Do not fabricate screenshots of unavailable baseline.

Shared interfaces fixed before worker edits:
- `RuntimeId = 'prime'|'pi'|'codex'`; `ExecutionScope = {connectionId:string;runtime:RuntimeId;sessionId:string;root:string}`; remote/local ID namespaces never silently translate.
- `TaskView` includes durable id/status/currentAttemptId optional/recovery review state; queue rendering consumes tasks, never assumes active session means running.
- `DocumentKey = {scope:ExecutionScope;path:string}`; `IdeFilePort.read(scope,path,maxBytes)` and `.write(scope,path,text,expectedBase?)` typed responses carry content/binary/truncated/error. Main enforces actual path ownership later.
- `SnapshotV1` mirrors current collaboration validator exactly; validate unknown input at runtime before any rendering.

P2A gates: npm ci from lock, typecheck/unit/parity tests, source build, complete package input/provenance/license inventory and no minified replacement dependency. Existing npm test and backend regressions still pass. Do not package/install a replacement user app or enable live adapters yet.

## P2B — Main/preload trust boundary, transport and storage

Dependency: synthetic P2A work may run in parallel with P1C.2/P1D. Connect the backend transport and credential lifecycle only after P1D authentication/configuration and readiness contracts are implemented and reviewed. Keep source PRs isolated from unfinished C2 implementation.

Outcome: trusted authored shell can use a fake local backend and fake Codex app-server through a narrow bridge; hostile embedded content cannot access privileged operations. This is the highest-risk increment and must be reviewed separately before expanding renderer functionality.

Worker A — main security/transport: main window/navigation/IPC validators; backend transport; credentials; data/asset store; no renderer UI. Worker B — Codex adapter/file access/approvals + isolated child lifecycle fixtures, no general main IPC registration. Worker C — preload/shared operation schemas + renderer client adapter tests; owns the central typed OperationMap, coordinating additions with A/B. Root/Astra reviews the contract before implementation; do not let each worker invent operation names.

Bridge contract:
- Preload exposes a frozen finite `DesktopBridge` with typed methods/operation map and unsubscribe functions; it never exposes ipcRenderer, arbitrary channel strings, arbitrary filesystem paths without ownership context, shell commands, arbitrary fetch URLs or raw IPC events.
- Every main handler validates event.sender identity AND event.senderFrame being the registered main frame at the trusted loaded document, then validates payload shape/length/types. Validation must occur for read-only operations too (clipboard, tokens/settings, files and metadata are privileged). Dev origin is exact and supported only for an unpackaged explicit development launch. Reject subframes, guest contents, destroyed/replaced windows, same-origin lookalikes and post-navigation stale frames.
- `connection.describe()` returns URL/configured/storage mode/generation, never the saved token. `connection.save({serverUrl,token})` accepts a new owner-entered token and returns description/probe state. Renderer may hold entry text only while entering it, then clear it. Main owns HTTP auth headers and token-bearing WebSocket/SSE transport; API operations map to fixed backend paths and methods, not arbitrary URLs supplied by renderer. Never attach coordinator token to redirects/new origins.
- `api.invoke<K extends OperationMap>(operation,payload)` only permits enumerated known operations. `api.subscribe(scope,cursor,listener)` main broker binds connection generation and origin; unsubscribe/connection switch aborts old requests and late notifications. Cursors are per server/connection, not a global number reused against another DB. Payloads/results/events carry supported v1 schema versions and bounded sizes; main returns sanitized structured errors.
- `localCodex.*` operations require known owned local IDs; no arbitrary thread/session import. Native approval answer is tied to exact request ID, process generation, thread/task, command/paths and one pending request; default deny on closing/navigation/timeouts/disconnect. User-facing dialog allows once only; no accidental persistent or fallback approval. Capability descriptions must stay honest for unknown protocol versions.

Navigation/browser boundary:
- Shell: contextIsolation true, nodeIntegration false, sandbox true; explicit CSP and no unsafe privilege expansion for preview convenience. Block privileged-window navigation/window-open to remote documents; external opens use validated allowlisted schemes and deliberate user action.
- Browser remote views use a separate unprivileged WebContentsView/partition with no Archon preload, Node or shared privileged session. Permission decisions validate requesting contents AND frame/origin; deny microphone/camera/etc by default and only allow app-approved audio capture from trusted shell upon explicit interaction. Do not copy historical global media grants.
- Assets: no bypassCSP custom scheme. Resolve against allowed private asset roots, reject traversal/encoded traversal/symlinks/unknown host and types, bound content, and sanitize/rasterize SVG appropriately using reviewed code. Imported SVG/content must not become executable UI. No arbitrary local-file serving. Remote pages cannot fetch private assets without intended scope.
- Disable historical in-place AppImage updater: metadata hash from same server is not release authorization, and it overwrites a live installed path. An inert compatibility method may return a clear unsupported-in-reconstruction result; no hidden install command.

Credentials/storage:
- Do not copy historical ARCHON_E2E_ALLOW_PLAINTEXT_SAFE_STORAGE toggle. Persist token only when the pinned Electron/OS backend is verified as protected (Linux fallback/basic-text mode is not adequate). Otherwise keep it in main-process memory and explain that it must be re-entered after restart. Unit mocks of safeStorage are not native keyring proof.
- Never return encrypted/plain token blobs to general settings API, logs, telemetry, renderer snapshots or exports. Reuse existing native auth via its runtime rather than inspecting credential stores.
- New profile storage is injected into all paths (including ~/.archon-style settings/assets, Chromium userData, Codex metadata), not just app.setPath('userData'). A fixture launch must not touch the real home or installed settings. Preserve normal data schema and establish migration using synthetic copies before any real import.
- Migration is explicit preview/copy with source/version inventory and untouched source backup, not automatic scanning of home. Unknown/future/corrupt records fail with actionable recovery; never reset silently. Preserve nonsecret unknown fields, asset references, local IDs, read-only flags and preferences. Do not change app identity in a way that silently migrates a Chromium profile or decrypts actual credentials without a separate authorized qualification run.

P2B gates: typed IPC positive/negative fixtures; main-frame/sender hostile tests; redirect credential containment; token sentinel absent from files/logs/general bridge; isolated memory-only/encrypted storage fixtures; local path traversal/protected file/symlink/cross-runtime denial; fake Codex accept/early-event/disconnect/approval/cancel lifecycle; fixture migration roundtrip and source immutability. Actual native hostile-frame/keyring tests are additionally required in P2D.

## P2C — Full behavior integration and fixture parity

Three workers can split renderer by ownership after B bridge stabilizes: (1) connection/settings/readiness+chat/session/project view models; (2) IDE/files/browser/workbench and navigation; (3) sharing/terminal/operations/appearance compatibility. One designated integration owner edits App/store/routes centrally, avoiding simultaneous edits. Every worker consumes the same validated bridge and runtime-scoped identities.

Port current candidate behavior listed above into readable React/TS modules. No arbitrary eval, DOM string injection or old bundle patch guards in this application. Preserve user-facing layout, themes and navigation organization. Old designs are comparison references; a component screenshot matching a design prototype alone cannot establish v0.3 parity.

Integration fixture matrix: remote Prime, remote Pi, local Codex; projectless scratch and named project; native Pi read-only; idle/queued/running/cancel requested/failed interrupted/completed; disconnected/reconnect/server-switch; missing/unverified runtime; dirty IDE tab before session/runtime switch; binary/truncated/failed file read; late read/save/event response; artifact links with line anchors; RTL/theme/font/sidebar preferences persisted; destructive actions demand their existing UI confirmation; no implicit trusted auto mode conversion from rejected approve/plan/chat-only. Sharing includes malicious/oversized/empty Unicode input and Stop/retry races.

Visible unsupported or unverified features remain clearly labeled and do not dispatch a fake success. Source reconstruction is not permission to drop candidate Browser/IDE/Codex/sharing behavior without an explicit parity limitation and follow-up gate.

## P2D — Isolated native qualification and packaging

Run only after unit/build boundary review and with explicit isolated profile paths plus fake backend/app-server. These tests may launch the built Electron binary but never a real agent/provider, real terminal session, native operational mutation or installed user profile. Do not run historical capture/provision scripts; new harness must prove all storage/env paths point into temporary fixture directories before launch. Use the desktop/browser tooling allowed by this environment for UI checks; do not bypass those boundaries with ad hoc automation.

Native gates:
- Launch packaged/unpacked app with sandbox intact; if host lacks sandbox/display support, record blocked gate rather than adding --no-sandbox as production configuration. Renderer-only tests remain separately labeled.
- Exercise shell preload availability only in trusted top frame; hostile iframe/new-window/remote view/navigation IPC attempts fail. Remote view compositing/resize/focus/destroy and permission-denial behavior must be observed in actual Electron.
- Isolated encrypted-keyring backend and unavailable/plaintext-backend paths: persist only in genuinely protected mode; no plaintext token in profile, logs, renderer storage or snapshots; restart behavior matches memory-only/persistent indicator. Use fake tokens exclusively. Missing host keyring support means that qualification is blocked, not passed through mocks.
- Local/remote routing, project/session selection, fake approval/cancel, reconnect/cursor, IDE editing/save/conflict/dirty tabs, browser links, terminal visibility, keyboard shortcuts, themes/RTL/profile persistence, sharing lifecycle all exercised against fixture services. No real network signaling required for initial peer fixture.
- Visual evidence at fixed sizes/themes/RTL with expected layout fixtures and manual review. If verified parent ASAR later appears, verify its exact hash then run the isolated canonical comparison harness; do not lower thresholds or alter official hashes to hide differences. Until then, v0.3 visual/native parity remains unverified.

Packaging gates:
- Two genuinely fresh workspaces/build directories run pinned npm ci/typecheck/tests/build/package. Record source commit/tree hash, Node/npm/Electron versions, lock hash, CI image/digest, architecture, packaged file manifest and SHA256, dependency/license manifest, and installer hashes. Do not assert byte-identical installers unless reproducibility is measured; timestamps/signing may differ, so compare normalized packaged inputs too.
- Build Linux x64 AppImage/deb first on supported host; arm64 is a distinct build/test gate. Do not claim arm64 from a config entry alone. No installation over official app, updater publication, signing/deploy/release operation in these source PRs.
- Package must launch without private ASAR and without source-reference directory access. Test artifact absence: native/release verification fails clearly if required executable/baseline/keyring evidence is missing; fast unit jobs may record separate expected skips but cannot turn missing mandatory release gates green.

## Publication/exit wording

Publish focused stacked review PRs A, B, C and D (split further if a review boundary warrants it). Each records source inputs reused, behavior delivered, checks actually run and unresolved native/parity gates. Do not include node_modules/build installers/profiles/secrets/private screenshots in Git. Publish each source increment from its actual GitHub parent commit.

P2A can honestly be complete when an authored isolated source build and tested pure models exist. P2B/C may be complete at their documented source/fixture boundaries. Full P2 remains open until the two fresh package builds and native acceptance checks pass, and the release-parity gaps are resolved or an explicitly accepted new-baseline qualification replaces comparison to unavailable v0.3 evidence. No successful legacy-source build alone changes the official baseline, P2/native credentials gate or permission to deploy.
