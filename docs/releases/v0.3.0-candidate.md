## Final behavior and implementation

- `current/candidate.cjs`: verifies the official parent, applies guarded patches, bundles the PeerJS client/license, permits its signaling WebSocket, syntax-checks the renderer, and writes a new ASAR.
- `current/ide-model.cjs`: extracts session code/file references and manages documents, loading/read-only states, saving and conflicts.
- `current/ide-renderer.js`: explorer, editor tabs, line numbers, copy/reload/save, keyboard save, panel resize/expand, terminal tab, and session reply actions.
- `current/collab-model.cjs`: bounded, validated sharing schema and Unicode snapshot-code serialization. Native tool/thinking records and unrelated metadata are excluded.
- `current/collab-renderer.js`: choose a session/project, review the selected content, create a peer invite or explicit snapshot code, receive/read shared content, and stop peer sharing. Project snapshots include the client's listed project sessions and available history, subject to existing API limits.
- `current/connection-renderer.js`: device-token entry through the existing write-only Electron bridge. The candidate also changes Test connection to check authenticated status after public health.
- `current/testing/`: disposable integration preview and separate verification records.
- `current/tests/`: patch, packaging/CSP, collaboration schema, code parsing, and document-state regressions.
- Root `package.json`: exposes the candidate builder without requiring users to change directory.

The collaboration/backend boundary is unchanged: no new routes, database tables, credentials, infrastructure, or background services are added to the current backend. PeerJS 1.5.4 is pinned in the lockfile and bundled from npm; no CDN script is injected at runtime. PeerJS service access still requires network connectivity.

## Reproduce setup, tests, build, and UI checks

1. Check out this branch and use Node.js 22.12+ with npm.
2. Run `npm run setup` to install the pinned current-kit dependencies.
3. Obtain the private official **unified-refresh** ASAR. Expected SHA-256: `36d3ae03bd6b20c4e9ea5fc690461ef972b16eb0c9433bfb1305daeb068e549b`. Do not substitute a differently labeled legacy archive.
4. Supply that archive to the tests so the actual renderer integration checks run:

   ```bash
   export ARCHON_V030_ASAR=/absolute/path/to/app-v0.3.0-unified-refresh.asar
   npm test
   npm run build:candidate -- "$ARCHON_V030_ASAR" /new/output/candidate.asar
   git diff --check
   ```

   The build refuses an existing output. Without the archive, archive-dependent integration tests can be skipped; this is not equivalent to the full recorded verification.

5. Start the disposable preview:

   ```bash
   node current/testing/preview.cjs "$ARCHON_V030_ASAR"
   ```

   Open `http://127.0.0.1:4318`. It contains synthetic sessions, files and project data. Real backend credentials must not be entered here. Stop the preview with Ctrl+C.

6. Check Sessions → fixture session → Open in IDE. Read a snippet, open its referenced file, edit and save with Ctrl+S, and open the reply's local preview URL in Browser.
7. In Share, choose the fixture project, Review snapshot, and Create peer invite. Open a second client, paste the code, and Open shared content. Verify both session transcripts. Stop sharing on the host and verify the receiving client reports disconnection.
8. For an offline export, choose Create snapshot code explicitly and paste the copied code into the other client's Share dialog. This code contains the reviewed data; it remains readable after the host stops sharing.
9. Check Settings → Connection. The device-token field uses the desktop bridge; Test connection checks authorization. The fixture result is only a UI check, not production authentication.

## Before actual work

The fixture preview is not the desktop runtime. Package and test the candidate in native Electron on the intended PC using isolated preferences and the [release checklist](../releases.md). In the actual app, apply the correct server URL, enter an existing device token if needed, test the connection, and choose the configured agent/model. Provider credentials belong to that runtime; sharing never provisions them.

Still unverified: real agent execution, native Browser compositing, live terminal transport, voice, live Skills/MCP inventories, backup/automation mutations, clean installation/update/rollback, and two-PC/Tailscale routing. Current collaboration is read-only snapshot sharing; it does not provide live co-editing, shared agent control, file synchronization, or persistent team membership.
