# v0.3.0 bug audit — 2026-09-12

Audited the current candidate against the official v0.3.0 archive. Changes are confined to bug fixes, regression tests, and documentation. Existing layouts and features are retained; the backend and installed app archives were not changed.

## Fixed

- **IDE drafts and saves:** stale confirmation callbacks cannot close or reload a saving file. Failed reloads preserve the current draft, and incomplete or malformed reads cannot produce an editable broken document. Saving and reloading cannot race each other.
- **IDE navigation:** unsaved tabs on another server still trigger the window-close guard. Disconnecting clears a pending explorer spinner. Keyboard resizing respects the viewport and Arabic direction.
- **Sharing lifecycle:** changing the selected session/project or sharing type cancels old reviews and peer invites. Cancelled project reviews stop fetching more sessions. A peer closing before receipt now reports failure, while a received snapshot stays readable.
- **Sharing validation:** payload limits count UTF-8 bytes so accepted Unicode snapshots can be reopened. Invalid sparse arrays are rejected before rendering.
- **Sharing dialog:** full-page Browser and Design surfaces now hide while Share is open and restore when it closes. Other open dialogs continue to keep those surfaces hidden.
- **Credentials:** delayed presence checks cannot overwrite successful saves. Missing bridge methods and failed writes recover with useful status; failed writes preserve the draft. Duplicate writes are blocked, and server changes or closing settings invalidate old callbacks. A failed refresh after saving no longer claims the token was not saved.
- **Connection testing:** a result from a previous server cannot appear as the current server's authenticated result. Closing settings invalidates the probe; duplicate clicks cannot start overlapping probes.

- Confirmed the displayed version is v0.3.0 and inspected the settings layout visually.
- Opened a fixture session, then its agent snippet in IDE. The snippet was read-only.
- Opened the referenced workspace file, edited it, and saved with Ctrl+S. The UI returned to Saved; the fixture write log contained the exact edited text.
- Browsed source files. Protected files were disabled; partial reads were read-only with Save disabled; failed reads displayed a recoverable error.
- Opened an agent-result URL in the browser panel and read the rendered greeting page.
- Reviewed a project containing two sessions, created a snapshot code, and confirmed changing sharing type removed the old review and code.
- Reopened that snapshot in the app and switched between its two session transcripts. Invalid codes displayed an error without crashing.
- Opened connection settings and verified stored-token status without reading or entering a credential.
- Ran Test connection against the fixture; it returned Authenticated connection.
- Reproduced the full-page browser surface remaining visible while Share was open. After the fix, the surface hid while Share was open and restored on Close. Browser runtime logs contained no errors or warnings.

## Verification boundaries

Regression tests use controlled asynchronous responses to exercise races that are difficult to reproduce by hand. The preview substitutes an iframe for Electron's native browser surface and a disposable bridge for the server. It does not prove live agent execution, credential persistence, terminal/voice transport, or cross-PC PeerJS/Tailscale routing. Existing read-before-write conflict detection is not an atomic server-side write lock.

This audit does not install or publish the resulting candidate. Earlier installation and two-client sharing evidence is recorded separately; it is not counted as a new live test here.
